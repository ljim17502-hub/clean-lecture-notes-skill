# 学习笔记工作流

将清洗后的逐字稿和可选课件转成学习笔记时，使用本参考。

## 资料优先级

1. 有课件时，课件提供主结构。
2. 清洗稿提供重点判断、案例、问答、现场演示、作业和实操提醒。
3. 早期课程的已有笔记可以提供风格和复习格式，但不能引入本节课没有出现的事实。

## 工作流

1. 搭建课程主干：
   - 提取课件标题、模块顺序和核心图示。
   - 如果没有课件，就从逐字稿里反复出现的转场提示和主题簇中推断主干。
2. 将逐字稿对齐到主干：
   - 把案例、点评和判断挂到相关模块下。
   - 将旁支讨论和核心知识分开。
   - 将项目要求和作业保留为行动项。
3. 写成复习版：
   - 从思维导图或知识地图开始。
   - 添加 5 分钟、20 分钟、45 分钟等按时间使用指南。
   - 在详细解释前放核心结论。
   - 在答案密集的部分前放主动回忆问题。
   - 将详细笔记组织成认知模型、章节或模块。
   - 有用时，加入面试话术、项目迁移话术或练习提示。
   - 加粗重点关键词和高价值句子，方便快速扫读。
   - 把正文改成学习者视角：写我应该记住什么、怎么判断、怎么迁移，不写课程发生过程。
4. 用“最强学习者”的标准审稿：
   - 检查不看逐字稿是否也能读懂笔记。
   - 检查每个重要概念是否有定义、例子和使用场景。
   - 检查可能的考试题或面试题是否覆盖。
   - 删除不帮助记忆或应用的装饰性章节。

## 视角转换规则

最终学习笔记不是课堂旁听记录、会议纪要或转述稿。清洗稿可以保留课堂顺序、说话人和待确认信息；学习笔记必须改写成“我自己整理、复习、迁移”的结构。

- 把“讲述者行为”改成“学习者结论”。例如“老师解释 X”改成“X 的关键理解是...”；“老师提到案例”改成“这个案例说明...”。
- 把“课程过程叙述”改成“知识结构”。例如“后面讲了项目文档”改成“项目文档体系包括...”。
- 把“材料位置描述”改成“可复用模块”。例如“原始文件末尾附带了一段流程笔记”改成“项目文档体系”或“完整工作流”。
- 把“录音/原稿里出现的说法”改成事实审计。能推断的术语直接归一化；不能确认且影响事实的内容放到资料来源与质量审计，不放进正文。
- 每一段都要能回答至少一个问题：我应该记住什么、怎么用、怎么迁移、容易错在哪里。

## 旁观者表达样例和改写

下面是样例，不是完整词表。同类表达都要改写，例如“老师提到 / 课上说 / 本节课讲了 / 录音里说 / 原稿里出现 / 文件末尾写着 / 上课时展示”等。

| 旁观者表达 | 推荐改写 |
|---|---|
| 老师解释 X | X 的关键理解是... |
| 课堂里提到一个案例 | 这个案例说明... |
| 本节课后面讲了项目文档 | 项目文档体系包括... |
| 录音里说某个工具待确认 | 资料来源审计：该工具名需谨慎核对。 |
| 原始文件末尾附带流程笔记 | 完整流程可以整理为... |

基础兜底样例包括：`老师`、`这节课`、`课堂里`、`老师播放`、`老师解释`、`待确认`、`原始文件末尾`。最终学习笔记不得只通过避开这些词来过关，必须整体呈现学习者视角。

## 推荐表达模板

- `我需要掌握的是...`
- `关键判断是...`
- `这个案例说明...`
- `可迁移到项目里的是...`
- `面试可表达为...`
- `实践时要注意...`

## 推荐笔记章节

选择适合当前内容的最小章节集合：

- 开篇提示或一句话目标。
- 思维导图或知识地图。
- 按可用时间划分的复习路径。
- 核心结论。
- 主动回忆自测。
- 核心模块或认知模型。
- 练习或工具操作复盘。
- 常见错误和排查路径。
- 面试话术。
- 项目迁移清单。
- 资料来源和质量审计。

## 思维导图规则

- 当课程超过三个模块，或用户要求导图时，使用思维导图。
- 分支标签要短。长解释放在正文，不要塞进导图。
- 最终学习笔记顶部应先出现 `思维导图`，用 Mermaid flowchart 或等价可视化白板呈现结构。
- 如果写入飞书，简单思维导图优先使用内嵌 Mermaid 或 Mermaid 白板；不要用纯文本树状代码块冒充导图。
- 如果使用飞书白板，必须验证它能渲染且不是空白。

## 加粗规则

- 对核心概念、方法、指标和关键判断的首次出现进行加粗。
- 对值得背诵或可直接用于面试的完整高价值句子进行加粗。
- 不要加粗整段、表格主体、资料来源列表，或同一术语的每一次重复出现。
- 先完成事实核对，再做加粗，确保加粗突出的是稳定结论，而不是不确定的 ASR 猜测。
- Markdown 使用 `**重点**`；飞书 XML 使用 `<b>重点</b>`。

## 术语归一化和待确认

- 清洗稿可以保留 `待确认` 或说话人标记，方便回查。
- 最终学习笔记不输出独立 `待确认` 章节。
- 可根据课件、上下文和常见工具名推断的术语，直接在正文中归一化，例如 `Remotion`、`HyperFrames`、`Pexels`、`Awwwards`、`Seedance`、`Image 2`、`i18n`。
- 不能确认且影响事实判断的内容，放入 `资料来源与质量审计` 的谨慎说明，不要混在正文里。

## 复习质量标准

如果结果只是段落摘要，就不是好笔记。它必须帮助学习者：

- 不重读全文也能回忆主结构。
- 用自己的话解释关键概念。
- 判断在真实产品或项目中应该怎么做。
- 通过问题和表格快速回看薄弱点。

## 风格默认值

- 除非用户要求其他语言，否则使用中文。
- 优先使用简洁标题、表格、清单和短段落。
- 使用加粗提升扫读效率，尤其是定义、判断规则、公式和可用于面试的句子。
- 将具体实操建议改写为“关键判断”“实践提醒”或“项目迁移项”。
- 避免夸大确定性；标注假设和未知信息。
